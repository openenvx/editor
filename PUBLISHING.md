# Publishing

Maintainer reference for building and publishing packages that leave this repository. Contributors should use the public package READMEs and [CONTRIBUTING.md](CONTRIBUTING.md) first.

> **Do not publish from an agent** - releases require maintainer credentials and review.

## What ships

| Package | Registry | What ships |
| --- | --- | --- |
| `@openenvx/html-studio` | npmjs (`registry.npmjs.org`, public) | Minified `dist/` ESM + CSS - `HtmlEditor` + host composition API + `./runtime` (`renderBlockDocument`) + `./theme.css` |
| `@openenvx/email-studio` | npmjs (`registry.npmjs.org`, public) | Minified `dist/` ESM + CSS - `EmailEditor` + `./runtime` (`renderEmailHtml`) + `./theme.css` |
| `@openenvx/canvas-studio` | npmjs (`registry.npmjs.org`, public) | Minified `dist/` ESM + CSS - `CanvasEditor` + `./runtime` (`createCanvasScene`) + `./theme.css` + `./fonts.css` |
| `@xmazu/openenvxee-extensions` | GitHub Packages (`npm.pkg.github.com`, restricted) | Sandbox author SDK - **not** part of the automated npm release workflow |

Scene model, preview descriptors, and editor runtime live in workspace `@openenvx/core` (`./schema`, `./preview`, `.`, `./react`). They are **not** published separately. Monorepo hosts use `@openenvx/canvas` / `@openenvx/html` / `@openenvx/driver-email` + `@openenvx/workbench` (HMR). Product host allowlists live on unpublished `@xmazu/openenvxee-studio` (`packages/studio`).

Export Worker lives in **openenvx-cloud** (`apps/export-service`), not this repo.

Everything else stays workspace-private and resolves from `src/` during local development.

**Hard rule:** published packages must **never** ship an `exports` `development` condition pointing at `src/`. Published tarballs are `files: ["dist"]` only.

## Versioning

The three public studio packages share **one version** per GitHub Release (`vX.Y.Z`).

Root [CHANGELOG.md](CHANGELOG.md) covers the **whole monorepo** (private packages are inlined into published tarballs). Generated by [git-cliff](https://git-cliff.org/) from conventional commits - see [cliff.toml](cliff.toml).

Preview unreleased notes locally:

```bash
bun run changelog
```

## Release workflow (maintainers)

Releases are **manual** via GitHub Actions - not on every push to `main`.

1. Open **Actions → Release → Run workflow** on `main`.
2. Choose bump: `patch`, `minor`, or `major`.
3. The workflow will:
   - compute the next semver (from the latest `v*` tag, or bump from current `package.json` when no tags exist)
   - set the same version on all three studio `package.json` files
   - update `CHANGELOG.md`
   - build and run `verify-pack` on each studio package
   - commit `chore(release): vX.Y.Z`, tag `vX.Y.Z`, and push
   - `npm publish --access public --provenance` for `html-studio`, `email-studio`, `canvas-studio`
   - create a GitHub Release with git-cliff release notes

If publish fails, re-run with **skip_bump** enabled to retry the same `package.json` version. Failed publishes no longer commit or tag on `main` (version bump happens only after npm publish succeeds).

Deleting git tags alone does **not** reset the version: `package.json` on `main` may already be higher from earlier failed runs, and `git-cliff --bump` uses the latest remaining tag. Reset studio `package.json` files manually when you need to re-ship an older semver.

Workflow: [`.github/workflows/release.yml`](.github/workflows/release.yml).

### npm publish auth

The release workflow reads GitHub Actions secret **`NPM_TOKEN`** (exact name). `401` on `npm whoami` means the job received a value but npm rejected it — not that the org secret is missing.

**GitHub (org secret):**

1. Organization → **Settings → Secrets and variables → Actions**
2. Secret name must be **`NPM_TOKEN`** (not `NPM_AUTH_TOKEN`, not a _variable_)
3. **Repository access** must include **`openenvx/editor`**
4. Remove any **repository-level** `NPM_TOKEN` on `openenvx/editor` that overrides the org secret with a bad value (repo secrets win over org secrets)

**npmjs.com (token):**

1. Log in as a user who can publish `@openenvx/*`
2. **Access Tokens → Generate New Token → Granular Access Token**
3. Permissions: **Packages and scopes → Read and write** for `@openenvx` (or each studio package)
4. Copy the token once (`npm_…`) into the GitHub secret — no quotes, no trailing newline

**Verify locally before re-running CI:**

```bash
npm whoami --registry https://registry.npmjs.org   # after: export NPM_TOKEN='npm_...'
```

The publish step trims whitespace, checks the `npm_` prefix, runs `npm whoami`, then `npm publish`.

Optional: you can also configure [npm trusted publishing](https://docs.npmjs.com/trusted-publishers) (OIDC, no token) for each package. If you use trusted publishing instead, remove `NPM_TOKEN` from the publish step and do not set `NODE_AUTH_TOKEN` in the job.

For trusted publishing, each package publisher must match this repo **exactly** (case-sensitive):

| Field                | Value         |
| -------------------- | ------------- |
| Organization or user | `openenvx`    |
| Repository           | `editor`      |
| Workflow filename    | `release.yml` |
| Allowed actions      | `npm publish` |

Each studio `package.json` must declare `repository.url` as `git+https://github.com/openenvx/editor.git` (with the matching `directory`).

The workflow uses `actions/setup-node@v7`, `id-token: write` (for `--provenance`), and `npm publish --access public --provenance`.

If publish fails after the version tag is already on `main`, re-run **Release** with **skip_bump** enabled (do not bump again).

### Verify before release

```bash
bun run verify-pack
```

Runs build + tarball checks for all three studio packages.

## External consumers (openenvx-cloud, etc.)

Legacy pins on `@xmazu/openenvxee-schema`, `@xmazu/openenvxee-preview`, `@xmazu/openenvxee-studio`, or `@xmazu/openenvxee-html-studio` are no longer published from this repo. Migrate to `@openenvx/html-studio` / inlined core as appropriate, or vendor Scene helpers - **not** by publishing `@openenvx/core`.
